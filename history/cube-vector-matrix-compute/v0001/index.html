1. 主题边界与核心结论

本页独立整理 Cube／Vector 与矩阵计算的讨论，不展开损失函数与反向传播推导。内容使用昇腾语境中的术语，但不针对具体芯片型号、算子内核或精度配置作保证。

Cube 的强项是密集矩阵乘累加与数据复用；Vector 的强项是灵活的批量逐元素运算。判断适合哪个单元，要看运算类型，不是只看数据是否为矩阵。

以下逻辑阵列、固定 k 的外积和流水线图用于解释计算组织，不代表某款芯片的实际电路、阵列大小或时钟安排。

2. 为什么矩阵加法通常用 Vector

矩阵加法的每个位置只计算 Cij = Aij + Bij。各位置相互独立，可以分批按向量指令处理：

A:    [ a0       a1       a2       a3 ]
        +        +        +        +
B:    [ b0       b1       b2       b3 ]
        ↓        ↓        ↓        ↓
C:    [a0+b0    a1+b1    a2+b2    a3+b3]

每对元素读进来、算一次、写回，通常主要受内存带宽限制。Cube 的强项则是矩阵乘累加 C ← AB + C：大量交叉配对与累加，让输入得到重复使用。融合的 AB+C 不意味着独立 A+B 也适合 Cube。

在训练计算中的例子

线性层 H = XW，令 G 为传入的输出梯度：

阶段计算运算本质通常适合
前向H = XW矩阵乘法Cube
权重梯度dW = XᵀG矩阵乘法Cube
输入梯度dX = GWᵀ矩阵乘法Cube
SGD 更新W ← W − ηdW逐元素缩放和相减Vector
AdamW 更新更新梯度历史状态与权重大量逐元素运算Vector

该表仅说明运算映射，不展开优化器的数学推导。实际执行路径与融合方式取决于芯片和软件实现。

3. 一个 2×2 例子：内积视角与外积视角

给定下面两个矩阵：

       A                 B
   [ 1   2 ]         [ 5   6 ]
   [ 3   4 ]         [ 7   8 ]

内积：一行 × 一列，把一个输出算完

左上角输出是 [1, 2] 与 [5, 7] 的内积，即 1×5 + 2×7 = 19。

一般形式：Cij = Σk AikBkj。

外积：一列 × 一行，给所有输出贡献一部分

累加位置A 的列向量B 的行向量外积贡献
k = 0[1, 3]ᵀ[5, 6]第一行 [5, 6]
第二行 [15, 18]
k = 1[2, 4]ᵀ[7, 8]第一行 [14, 16]
第二行 [28, 32]

把两批贡献相加：

[  5    6 ]     [ 14   16 ]     [ 19   22 ]
[ 15   18 ]  +  [ 28   32 ]  =  [ 43   50 ]

一般形式：C = Σk A:,kBk,:。

内积视角是盯着一个输出，把它算完；外积视角是共享一批输入，同时推进多个输出。两者数学上完全等价，只是遍历与组织方式不同。实际可以把乘积直接累加到输出状态中，不必先物化每个完整的外积矩阵。

4. 核心澄清：32 个数、256 次乘加和 16 对向量

本节固定讨论 A、B 都是 16×16 的矩阵。先看一个 k，再看全部 16 个 k；不能把这两个层级混在一起。

第一层：一个 k，对应一对向量

  • A 的第 k 列：一个列向量，包含 16 个标量。
  • B 的第 k 行：一个行向量，包含 16 个标量。
  • 合计 32 个不同的 A／B 输入标量，不是 32 条向量。

这两组元素全部交叉配对，不是只按相同下标配成 16 对：

a0  → a0*b0,  a0*b1,  ... , a0*b15     16 pairs
a1  → a1*b0,  a1*b1,  ... , a1*b15     16 pairs
...
a15 → a15*b0, a15*b1, ... , a15*b15    16 pairs

                                16 × 16 = 256

每对执行 Cij ← Cij + AikBkj，因此一对向量贡献 256 次乘加。已有的 256 个输出累加值不包含在“32 个新输入标量”中。

第二层：完整乘法包含 16 对向量

k向量对贡献
0A 第 0 列 × B 第 0 行256 次乘加
1A 第 1 列 × B 第 1 行256 次乘加
………
15A 第 15 列 × B 第 15 行256 次乘加
合计16 对向量4096 次乘加
16 对向量 × 每对 256 次乘加 = 4096 次乘加。
按每次乘加计 2 FLOPs，共 8192 FLOPs。所有贡献都累加到同一个 16×16 输出矩阵。

“32”与“256”不是单位换算

输入数目是两组大小相加：16+16；配对数目是两组大小相乘：16×16。中间桥梁是每个 A 与所有 B 配对，每个输入被使用 16 次。

先前讨论中“32 个输入 → 256 次乘加”的表述只覆盖了一个 k，并省略了交叉配对以及全部 k 的累加。本节补齐这两环。

5. Cube 的优势：不仅算得多，还要持续喂得饱

优势一：阵列内部的数据复用

在上述一个 k 的示意中，256 次乘加产生 512 次 A／B 操作数使用，但只涉及 32 个不同输入。通过广播、转发等内部数据通路，一个数可以供多个乘累加单元使用。

这不等于显存访问一定减少 16 倍。真实流量取决于缓存、分块、布局和具体实现。这里展示的是不同输入数量与操作数使用次数之间的区别。

优势二：局部保存累加状态

每个逻辑输出位置保存自己的累加结果，后续乘积不断加入，不需要每次乘加都把中间结果写回显存。单元的核心动作可写为 s ← s + a×b。

优势三：大量专用乘加硬件与块级组织

Vector 也可以做乘加和矩阵乘法，并非没有数据复用。Cube 的价值在于把密集矩阵乘法需要的乘累加能力、数据通路和块级控制专门化，以通用性换取该类工作负载的效率。

实际分块不只是“一列乘一行”

对 CM×N = AM×KBK×N，工程上通常选择输出块，并沿 K 分批累加：

Ctile += AMtile×Ktile BKtile×Ntile

  • M、N 方向分块：选择本次计算哪些输出。
  • K 方向分块：选择本次累加哪些贡献。
  • 外积展开是理解视角，不是某款 Cube 唯一的执行方式。

优势四：数据搬运与计算重叠

time →
load:     [ tile 0 ][ tile 1 ][ tile 2 ]
compute:           [ tile 0 ][ tile 1 ][ tile 2 ]

这是理想流水线示意。通过缓冲，在计算当前块时准备下一块，减少等待；实际能否重叠及收益大小需要具体内核与测量验证。

矩阵太小、形状不匹配、数据供给不足、矩阵向量乘法缺少一个方向的复用时，Cube 可能无法充分利用。逐元素运算也不会自然获得这种交叉配对收益。

Cube 不只是“计算器多”，而是“计算器多，而且能通过数据复用与流水线持续供数”。

6. 运算量口径与本页边界

n³ 与 2n³ 并不矛盾

经典的两个 n×n 矩阵相乘，每个输出需要 n 次乘法和 n−1 次加法，一共有 n² 个输出：

统计口径数量
乘法次数n³
经典点积算法的乘法与加法次数2n³ − n²
从零累加执行 n³ 次 MAC，每次计 2 FLOPs2n³
经典算法的渐近复杂度O(n³)

因此 16×16 例子的 8192 FLOPs 使用 MAC 统计口径；若按经典点积算法计纯 AB 的乘法与加法，则为 7936 次算术操作。区别来自是否把第一次乘积与零的累加也计入，两种口径应说明清楚。
